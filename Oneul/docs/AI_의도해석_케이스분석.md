## 3. 학원 특화 케이스 (시간 맥락 모델 적용)

`FastScheduleParser.resolveBareHour` — 오전/오후 미표기 맨숫자(1~12시)만 해당.
과목/학원 컨텍스트 = 제목에 과목명(수학·영어·국어…) 또는 학원/과외/특강/수업 등 포함.

| # | 조건 | 판정 | 근거(시간맥락모델 §) |
|---|---|---|---|
| A1 | 오전/오후/새벽/아침/저녁/밤 명시 | 그대로 | 사용자 명시 최우선 |
| A2 | 같은 제목 기존 일정에 h 또는 h+12시 존재 | 그 시각(질문 생략) | 학습 패턴 > 통계 모델 |
| A3 | 12시 | 낮 12시 | 점심 평균 12:25 |
| A4 | 1~7시 | 오후(h+12) + 근거 표시 | 새벽 배제 — 전 활동에서 새벽 시작 희박 |
| A5 | 8~11시 · 주말 또는 방학 | 오전 | 주말 오전반·방학 특강 08시 등원 |
| A6 | 8~9시 · 학기중 평일 · 과목 | 저녁(h+12) + 근거 표시 | 오전 8~9시=등교 시간, 저녁 수업 17~22시 |
| A7 | 10~11시 · 학기중 평일 · 과목 | 확인 질문 | 오전=수업 중, 22시 시작=조례 위반 구간 |
| A8 | 8~11시 · 방학 불명 평일 · 과목 | 확인 질문 | 학기중(PM)↔방학(AM) 판정이 뒤집히는 구간 |
| A9 | 8~11시 · 평일 · 비과목 | 오전 | 병원·회의 표준 09~18시 |
| A10 | 방학 판정 | 학사일정의 방학/개학 이벤트 | 데이터 없으면 불명 → A8 |

확인 질문 문구: **"'국어' — 오전 10시인가요, 오후 10시인가요?"** + [오전 10시] [오후 10시] 버튼
(1회 1질문, 선택 즉시 미리보기로 이동). 근거 표시 문구: **"오후 5시로 해석했어요 — 아니면 눌러서 고쳐 주세요"**.

## 4. 알고리즘 플로우 (의사코드)

```
입력 텍스트
├─ 한글 수사 정규화("한시"→"1시")
├─ [게이트] 질문/급식/외형/후속 단어? ─→ 모델
├─ [게이트] 수정 단어? ──→ tryParseEdit (규칙 수정)
│     대상 = 제목 일치(가장 긴) → 날짜·기존시각으로 좁힘
│     새값 = '…로/으로' 앞의 시각/날짜, 맨숫자는 원래 시각과 가까운 해석
│     실패 → 모델(단, 삭제 단어 없으면 모델의 delete 무시)
├─ [게이트] 삭제 단어? ──→ 모델 → 후보 1개면 미리보기, 여럿이면 확인 질문
└─ 생성(FastScheduleParser.parseEvents)
      ├─ 세그먼트 분리: 줄/쉼표/'그리고' + 시각 보유 시 날짜 토큰 앞 분할
      ├─ 조각별: 날짜(이월) · 시각 · 제목 · 반복(요일 뭉치 포함) 추출
      ├─ 실패 조각 존재(다중 시각·기간·잔여 숫자) → 전체 모델 폴백
      └─ 맨숫자 시각 → resolveBareHour(§3) → 확정/근거표시/확인질문
결과 = 미리보기 카드(수정 가능) → "적용하기" 눌러야 저장 (파괴적 작업 2단계 확인)
```

### 알려진 한계 (향후)

- "일월 정산"처럼 요일 글자로만 된 일반 단어는 반복으로 오인 가능(드묾).
- 두 단어 장소구("회의 강남역에서")는 모델 폴백(제목까지 장소로 흡수되는 기존 한계).
- C18(중복/충돌 감지)은 미구현.
- 범위 삭제는 사용자 일정만 대상(시간표·학사일정 제외). 범위+제목 조합 필터("다음주 수학만 다 지워")는
  범위 내 전체를 미리보기로 보여주므로 사용자가 목록에서 확인 — 자동 필터는 향후.
- 학원 22시 이후 조례는 시도별 차이 — 지역 설정 도입 시 A7을 지역별로 완화 가능.
