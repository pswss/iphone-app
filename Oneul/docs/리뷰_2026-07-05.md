# Oneul — UI / UX / 기능 리뷰

> 작성: 2026-07-05 · 방식: 7개 관점(맥·iOS·메모·학생기능·완성도·기능공백 + 크리틱) 병렬 코드 리뷰  
> 대상: SwiftUI 앱 Oneul (iOS 26 / macOS 26)

## 잘된 점

- MacWeekGrid의 7열 통합 세로 스크롤 + 종일/멀티데이 연속 스팬 밴드(행 패킹, 주 경계 open-edge 각처리)는 구조 설계가 탄탄함 (TodayView.swift)
- 플랫폼 분기가 성실함 — 맥 전용 더블클릭 추가·클릭-드래그 즉시 이동(롱프레스 지연 제거), 첫 열만 시각축, 고정 요일 헤더 등 (DayGridView.swift)
- ⌘N/⌘T 메뉴 명령, Settings 씬(⌘,), MenuBarExtra 등 macOS 씬 구성의 기본기를 갖춤 (OneulApp.swift)
- 그리드 상호작용 디테일이 애플 캘린더급으로 정교함 — 공유 스크롤 위치(scrollHour), 드래그 중 가장자리 자동 스크롤·5분 스냅·햅틱, 드래그 중 페이저 좌우 스와이프 잠금 등 (DayGridView.swift, TodayView.swift)
- AI 결과를 즉시 적용하지 않고 미리보기 카드 + 항목별 수정 시트를 거쳐 '적용하기'로 확정하는 안전한 흐름 (AIScheduleView.swift)
- 성능을 의식한 구조 — DayPager 3페이지 재사용, 날짜별 이벤트 인덱스(rebuildIndex), 접힘 진행률과 그리드 재생성 분리(gridToken) (TodayView.swift)
- 리치 텍스트를 CloudKit 안전한 Data로 아카이브하면서 평문 text를 함께 동기화 유지해 목록 미리보기·내보내기에 재활용하는 모델 설계가 견고함 (Memo.saveRich/loadRich). 실제로 SwiftUI Font 속성이 JSON 왕복에서 살아남는 것도 테스트로 확인됨
- txt/md 내보내기, QuickLook 첨부 미리보기, 사진/파일 첨부, 보안 스코프 리소스 처리 등 핵심 기능이 iOS/macOS 양 플랫폼 분기와 함께 잘 갖춰짐
- Persistence.swift의 App Group/CloudKit entitlement 부재 시 크래시 없는 로컬 폴백 처리가 사려 깊음
- 선택과목 자동 판별 설계가 독창적 — 학년 전체 반 시간표를 병렬 조회해 '일부 반만 듣는 과목=선택과목'을 추론하고, 체크→자동배치→미리보기 수정 2단계 흐름과 '선택 아님' 롱프레스 오버라이드까지 갖춤 (NEIS.swift analyzeGrade, ElectiveSetupView.swift)
- 갱신 파이프라인이 견고 — 하루 1회 자동 재임포트, 네트워크 실패 시 기존 데이터 보존(classTT 비면 중단), 시험일·방학·공휴일 수업 제외, CloudKit 멀티기기 중복 정리(dedupBySource)까지 실데이터 엣지케이스를 폭넓게 처리 (NEIS.swift)
- 온보딩 마찰 축소 디테일 — classInfo API로 실제 반 목록을 피커에 반영, 학교급별 학년 범위 보정, 시험주 공백을 직전 정상 주로 backfill하는 등 NEIS 데이터의 함정을 잘 우회 (SchoolSetupView.swift, NEIS.swift)
- Theme.swift의 dynamic(light:dark:) 색 시스템과 AppChrome의 플랫폼 추상화(햅틱·키보드·외형)가 깔끔하고, iOS 26 glassEffect를 카드·메뉴·FAB에 일관 적용해 시각 언어가 통일돼 있음
- DayGridView의 상호작용 완성도가 높음 — 드래그 이동·양끝 리사이즈·가장자리 자동 스크롤(속도 가변)·5분 스냅마다 햅틱 스텝 등 애플 캘린더 수준의 디테일
- tr() 단일 경로 i18n 시도와 위젯·워치·Live Activity까지 스냅샷(isEnglish 포함)을 공유하는 구조 등 멀티 표면 설계가 잡혀 있음
- 위젯 생태계가 이미 탄탄함 — 홈/잠금 위젯, Live Activity, 워치 앱 + 컴플리케이션까지 App Group 스냅샷 기반으로 일관되게 구현 (OneulWidgetBundle.swift, OneulWatchWidgetBundle.swift)
- 데이터 계층이 견고함 — 멀티데이 occurs(on:), CloudKit 멀티기기 중복 정리(dedupBySource), 출처(source) 태그로 시간표 재가져오기 시 사용자 일정 보호 (ScheduleEvent.swift)
- 규칙 기반 빠른 파서 → 온디바이스 AI 폴백의 2단 설계가 명확하고, '전체를 소화 못 하면 통째로 폴백' 원칙으로 부분 유실을 방지 (FastScheduleParser.swift)

## 우선 처리 순서 (권장)

데이터 안전 → 신뢰 → 매일 보이는 것 → 발견성 순.

1. **데이터 손실 차단** — 클립보드 영구 유지 버그, 반복 일정 편집 시 회차 삭제, 자동 갱신이 사용자 수정 원복
2. **알림 파이프라인** — 앱 안 열어도 예약 유지, 포그라운드 알림, 하루 전 옵션, 설정 내 알림 섹션
3. **라이트모드 대비** — 일정 블록 배경/글자 대비, `.white` 하드코딩 구분선·현재선
4. **통합 검색** — 일정 + 메모
5. **맥 상호작용** — 우클릭 컨텍스트 메뉴, 그리드 재생성(스크롤/선택 소실), 요일 간 드래그 이동
6. **온보딩** — 학생 기능(급식·시간표) 첫 실행 유도
7. **접근성** — accessibilityLabel/Action, Dynamic Type

## macOS 네이티브 UX

### 🔴 심각 — 단축키 체계 전도 + ⌘←/→가 주 그리드에서 사실상 무반응

**파일**: `Oneul/OneulApp.swift, Oneul/Features/Today/TodayView.swift`

OneulApp.swift의 메뉴 명령은 ⌘←/→ = '이전 날/다음 날'(±1일)인데, TodayView.swift의 macDayNav는 수식키 없는 ←/→ = ±1주다. 관례(수식키가 클수록 큰 단위)와 반대일 뿐 아니라, 맥 화면은 주 그리드이고 dayHeader는 '오늘'만 강조할 뿐 selectedDay를 어디에도 표시하지 않으므로, 같은 주 안에서 하루 이동(⌘←/→)하면 화면에 아무 변화가 없다. 7번 중 6번은 메뉴가 고장난 것처럼 보인다.

**개선안**: 맥에서는 ⌘←/→를 주 이동으로 통일하고 메뉴 라벨을 '이전 주/다음 주'로 변경(macDayNav의 bare 화살표와 일원화). 하루 단위 선택이 필요하면 주 그리드의 dayHeader에 selectedDay 강조를 추가해 이동이 보이게 할 것.

### 🔴 심각 — 일정 드래그·리사이즈·추가 때마다 주 그리드 전체가 재생성되어 스크롤·선택이 리셋됨

**파일**: `Oneul/Features/Today/TodayView.swift`

MacWeekGrid에 .id(gridToken)이 붙어 있고 gridToken은 indexVersion·showingAdd·addStart를 포함한다. 드래그/리사이즈 커밋(context.save) → events 변경 → indexVersion 증가 → MacWeekGrid 아이덴티티 변경 → 전체 재생성 → didInitialScroll이 초기화되어 스크롤이 '현재 시각-1h' 앵커로 점프하고 DayGridView의 selectedID(선택 상태)도 소실된다. 더블클릭 추가도 showingAdd 변경으로 즉시 같은 리셋을 유발한다. 리사이즈는 선택 상태가 전제인데 커밋마다 선택이 풀려 연속 조정이 불가능하다. 게다가 맥 경로는 MacWeekGrid가 DayGridView에 previewStart를 전달하지 않아 showingAdd/addStart를 토큰에 넣을 이유 자체가 없다.

**개선안**: .id(gridToken)을 제거하고 데이터 변경은 상태 기반으로 갱신. 바깥 ScrollView에 scrollPosition 바인딩(이미 scrollHour @Binding이 넘어오지만 미사용)을 연결해 스크롤 위치를 보존하고, 선택 상태를 상위로 끌어올려 유지.

### 🔴 심각 — 우클릭 컨텍스트 메뉴 부재 — 잘라내기/복사/복제/삭제가 '4px 이상·세로 3px 미만 가로 드래그 후 릴리즈'라는 발견 불가능한 경로로만 열림

**파일**: `Oneul/Features/Today/DayGridView.swift`

grep으로 확인: .contextMenu, onDeleteCommand, onHover 모두 없음. 커스텀 eventMenu는 endMove에서 dragMinutes==0일 때만 뜨는데, macOS LongPressArea(DragGesture minimumDistance:4)는 4px 이상 끌어야 시작되고 dragMinutes는 세로 약 3px부터 5분 스텝이 되므로, 메뉴를 띄우려면 '거의 순수한 가로 드래그 후 릴리즈'가 필요하다. 맥 사용자의 기본 기대(우클릭)와 완전히 어긋나고, 선택된 일정에서 Delete 키 삭제, Edit 메뉴/⌘C·⌘V·⌘X·⌘D 연동도 없다.

**개선안**: 일정 블록에 .contextMenu(잘라내기/복사/복제/삭제) 추가, 선택 상태에 .onDeleteCommand 또는 Delete 키 처리, 빈 곳 우클릭에 '여기에 붙여넣기'. 시스템 Edit 메뉴와 단축키를 연결해 맥 표준 편집 모델을 따를 것.

### 🔴 심각 — 주 그리드인데 일정을 다른 요일로 드래그 이동 불가 + 가로 드래그가 오동작 유발

**파일**: `Oneul/Features/Today/DayGridView.swift`

이동 제스처(changeMove/commitDrag)가 translation.height만 사용한다. 주 뷰에서 가장 기본적인 상호작용(이벤트를 옆 요일 열로 끌기, Apple Calendar 표준)이 불가능하다. 사용자가 가로로 끌면: 세로 성분이 3px 미만이면 예상 밖의 iOS식 말풍선 메뉴가 뜨고, 3px 이상이면 시간이 5분 단위로 미세하게 어긋나며 저장된다 — 두 경우 모두 의도와 다른 결과다.

**개선안**: 맥 주 그리드에서 드래그의 가로 성분을 열 폭으로 나눠 일 단위 이동(cal.date(byAdding:.day))을 지원. 최소한 가로 우세 드래그는 커밋하지 않고 취소해 오동작을 막을 것.

### 🔴 심각 — 일정을 한 번 복사하면 이후 모든 빈 곳 더블클릭이 조용히 '붙여넣기'로 영구 전환

**파일**: `Oneul/Features/Today/DayGridView.swift`

addAt(y:)는 EventClipboard.item이 있으면 새 일정 편집기 대신 복사본을 즉시 생성한다. grep으로 확인: EventClipboard.item은 copy()에서 설정만 되고 어디서도 nil로 해제되지 않는다. 즉 세션 중 복사/잘라내기를 한 번이라도 하면 '빈 곳 더블클릭 → 새 일정'이라는 기본 동선이 사라지고, 아무 시각적 모드 표시 없이 계속 복제본이 생긴다. 툴바 +로만 새 일정을 만들 수 있게 되어 사용자를 혼란시킨다.

**개선안**: 붙여넣기를 더블클릭에 오버로드하지 말고 컨텍스트 메뉴 '붙여넣기'/⌘V로 분리. 유지하려면 최소한 붙여넣기 1회 후 클리어하고, 붙여넣기 모드임을 커서·배너 등으로 표시할 것.

### 🟡 중간 — ⌘N과 툴바 '+' 버튼이 섹션에 따라 아무 일도 안 함(죽은 버튼)

**파일**: `Oneul/OneulApp.swift, Oneul/RootView.swift`

oneulNewEvent 수신자는 TodayView 하나뿐(grep 확인). RootView의 switch가 섹션별로 뷰를 교체하므로 메모/급식 섹션에서는 ⌘N('새 일정')이 무반응이다. 급식 섹션에서는 툴바 +가 '새 일정' 라벨로 oneulNewEvent를 쏘지만 수신자가 없어 클릭해도 아무 일도 일어나지 않는다. NotificationCenter 기반 라우팅의 구조적 한계.

**개선안**: RootView가 oneulNewEvent를 받아 macSection을 .today로 전환한 뒤 시트를 띄우거나, 시트 상태를 RootView로 끌어올릴 것. 급식 섹션에서는 + 버튼을 숨기거나 비활성화.

### 🟡 중간 — 요일 헤더가 아래 7열과 정렬이 어긋남(왼쪽 열일수록 최대 ~40pt 오프셋)

**파일**: `Oneul/Features/Today/TodayView.swift`

MacWeekGrid 헤더는 dayHeader.frame(maxWidth:.infinity) 바깥에 .padding(.leading, i==0 ? 52 : 0)을 더해 첫 셀 폭이 flex+52가 된다. 결과적으로 헤더 셀 폭은 (W-52)/7, 아래 DayGridView 열 폭은 W/7로 서로 다르다. 창 폭 1000pt 기준 두 번째 요일 헤더 중심이 해당 열 중심보다 약 41pt 오른쪽에 놓이고 오른쪽으로 갈수록 수렴한다 — 날짜 숫자가 자기 열 위에 정확히 얹히지 않는다.

**개선안**: 헤더도 열과 동일한 7등분 HStack으로 만들고, 첫 셀 '내부'에 52pt 거터를 두거나(예: 콘텐츠에 .padding(.leading, 52) 후 프레임), 헤더 HStack 전체를 leading 52 패딩하고 폭을 W-52로 맞춰 열 계산과 일치시킬 것.

### 🟡 중간 — 리사이즈 핸들이 완전히 비가시 — 커서 변화·호버 피드백 없음

**파일**: `Oneul/Features/Today/DayGridView.swift`

리사이즈는 클릭으로 선택한 뒤에만 활성화되며, 핸들은 위/아래 16pt의 Color.clear다. onHover/NSCursor(resizeUpDown/pointingHand)가 파일 어디에도 없어(grep 확인) 맥 사용자가 리사이즈 가능 여부를 알 방법이 선택 시 코너 곡선 하이라이트뿐이다. 마우스 정밀 포인팅이 가능한 맥에서 어포던스가 iOS보다도 약하다.

**개선안**: 선택(또는 호버) 시 상·하단에 가시적 핸들 표시, 핸들 영역 .onHover에서 NSCursor.resizeUpDown, 블록 본문에서 pointingHand로 커서 전환.

### 🟡 중간 — '급식'이 사이드바 섹션과 툴바 시트로 이중 존재 — 급식 섹션 위에 같은 뷰가 시트로 또 뜸

**파일**: `Oneul/RootView.swift`

급식은 사이드바 섹션(MacSection.meal)이면서, 툴바에도 급식 버튼이 있어 MealView를 모달 시트로 띄운다. 툴바는 모든 섹션에 공통이라 급식 섹션에 있는 상태에서도 버튼이 보이고, 누르면 자기 자신과 같은 화면이 시트로 겹친다. 전체 섹션급 콘텐츠를 모달 시트로 띄우는 것 자체가 macOS 관례(사이드바 전환/별도 창)와 맞지 않는다.

**개선안**: 툴바 급식 버튼은 시트 대신 macSection = .meal 선택으로 바꾸거나 제거. 빠른 확인 용도라면 팝오버(오늘 급식 요약) 정도로 축소.

## 기능 공백 (제품 레벨)

### 🔴 심각 — 알림이 '앱을 열어야만' 예약됨 — 2일 이상 앱을 안 열면 리마인더가 끊김

**파일**: `Oneul/Notifications/NotificationManager.swift, Oneul/Features/Today/TodayView.swift, Oneul/LiveActivity/BackgroundRefresh.swift`

NotificationManager.reschedule()는 48시간 이내 일정에만 1·2차 알림을 예약하는데, 호출처가 TodayView.syncLiveActivity() 하나뿐이다(onAppear/onChange/시트 닫힘, TodayView.swift:406). BackgroundRefresh.handle()은 Live Activity·워치만 갱신하고 알림 재예약을 하지 않는다. 즉 사용자가 이틀 넘게 앱(그중에서도 '오늘' 탭)을 열지 않으면 그 이후 일정의 알림은 전혀 오지 않는다. CloudKit로 다른 기기(맥)에서 추가한 일정도 아이폰에서 앱을 열기 전까지 알림이 예약되지 않는다. 리마인더는 캘린더 앱의 핵심 신뢰 기능인데 현재 구조는 '자주 여는 사용자'에게만 동작한다.

**개선안**: ① BackgroundRefresh.handle()에서도 NotificationManager.reschedule() 호출. ② 48시간 창을 없애고 iOS 64개 한도 내에서 시간순으로 앞에서부터 채우기(가까운 일정 우선, 남는 슬롯에 먼 일정). ③ CloudKit 원격 변경 수신(NSPersistentCloudKitContainer 이벤트나 scenePhase active) 시에도 재예약.

### 🔴 심각 — 반복 일정 편집 시 '이 일정만 수정' 불가 + 요일·종료일 정보가 조용히 유실됨

### 🟡 중간 — EventKit 미지원 — 시스템 캘린더와 완전 단절, 일정 내보내기도 없음

### 🟡 중간 — 설정에 알림 섹션이 없음 — 권한 거부 복구 불가, 시험 전날 알림은 강제

### 🟡 중간 — 알림 옵션 최대 '1시간 전' — 종일 일정(학사일정·D-day)에 하루 전 알림 불가, 집중 모드도 못 뚫음

reminderOptions가 없음/정시/5/10/30/60분(EventEditorView.swift:31-33)까지라 '하루 전/이틀 전' 알림을 걸 수 없다. **개선안**: reminderOptions에 '하루 전(오후 9시 등)' 추가하고 종일 일정은 이 옵션을 기본값으로. Time Sensitive Notifications entitlement를 받아 시작 임박 알림에 .timeSensitive를 지정.

### 🟢 사소 — 시험 판별이 제목 contains 기반이라 오탐 — '시험공부' 일정에도 전날 준비물 알림 발송

**개선안**: '공부/준비/정리/복습/범위' 등 제외 키워드를 두거나, 시험 알림 예약 전 사용자에게 표시되는 배지(일정 카드에 '시험' 태그)를 붙여 오인 시 사용자가 해제할 수 있게 하라.

## 크리틱 — 추가 발견

### 🟡 중간 — 일정 색이 '그날의 시간순 인덱스'로 자동 배정 — 일정 하나만 추가·이동해도 그날 모든 일정 색이 바뀌고, 색을 지정할 방법이 없음

**파일**: `Shared/EventPalette.swift, Oneul/Models/DayPlan.swift, Oneul/Features/Today/DayGridView.swift`

DayGridView.swift:207에서 블록 색을 `EventPalette.color(plan.colorIndex(of: e), of: plan.events.count)`로 계산하는데, colorIndex는 DayPlan의 '시간순 정렬 배열 인덱스'(DayPlan.swift:72-74)다. 즉 아침에 일정 하나를 추가하면 그날 나머지 모든 일정의 색이 한 칸씩 밀려 바뀌고, 8개 이상이면 보간 색(EventPalette.swift:27-38)이라 개수 변화만으로도 전체 색이 미묘하게 변한다. 같은 반복 수업(예: '수학')도 요일마다 그날 몇 번째냐에 따라 색이 달라져, 시간표 앱의 기본 기대인 '과목별 색 일관성'이 성립하지 않는다. 사용자가 색/카테고리를 고를 UI는 어디에도 없다(EventEditorView에 해당 필드 없음). '내 일정 색이 갑자기 왜 바뀌었지'라는 혼란과 색을 기억 단서로 쓸 수 없는 문제를 만든다.

**개선안**: 이벤트에 사용자 지정 colorIndex(옵셔널) 속성을 추가해 편집기에서 선택 가능하게 하고, 미지정 시에는 seriesID나 제목 해시 기반의 '안정적' 자동 색을 배정해 일정 추가·이동으로 다른 일정 색이 바뀌지 않게 한다. 무지개 그라데이션 컨셉을 유지하려면 최소한 시간표(source=timetable)만이라도 과목명 해시로 고정 색을 준다.

### 🟡 중간 — 알림 델리게이트 부재 — 앱 사용 중에는 리마인더가 소리 없이 사라지고, 알림을 탭해도 해당 일정·날짜로 이동하지 않음

**파일**: `Oneul/Notifications/NotificationManager.swift, Oneul/OneulApp.swift`

프로젝트 전체에 UNUserNotificationCenterDelegate 구현이 없다(grep 결과 0건). iOS 기본 동작상 delegate의 willPresent가 없으면 앱이 포그라운드일 때 알림 배너·사운드가 표시되지 않으므로, 사용자가 메모를 쓰거나 급식을 보는 중에 '10분 전' 리마인더가 조용히 증발한다. 일정을 보라고 알림을 보내는 앱인데 앱을 켜두면 알림이 안 오는 역설이다. 또 didReceive(response:) 핸들러도 없어 알림을 탭하면 마지막에 쓰던 탭이 그대로 열릴 뿐, 해당 일정이나 날짜로 이동하지 않는다. Live Activity의 widgetURL("oneul://today", ScheduleLiveActivity.swift:64)도 앱 쪽에 onOpenURL 처리가 전혀 없어 URL 스킴만 등록돼 있고 실제 라우팅은 없다.

**개선안**: OneulApp에서 UNUserNotificationCenter.delegate를 설정해 willPresent에서 .banner/.sound를 반환하고, didReceive에서 알림 id(이벤트 UUID가 이미 identifier에 들어 있음)로 오늘 탭 + 해당 날짜/일정 하이라이트로 딥링크한다. onOpenURL로 oneul:// 스킴도 같은 라우터에 연결한다.

### 🟡 중간 — 일정에 메모·설명을 적을 수 없음 — 모델에 notes 필드가 있지만 이를 보여주거나 편집하는 UI가 프로젝트 어디에도 없음

**파일**: `Oneul/Models/ScheduleEvent.swift, Oneul/Features/Editor/EventEditorView.swift`

ScheduleEvent.notes(ScheduleEvent.swift:13)는 선언·초기화만 되어 있고, EventEditorView에는 제목·장소·시간·알림·반복·주요일정 필드뿐 메모 입력란이 없다. 그리드 블록·워치·위젯 어디에서도 notes를 읽지 않는다(사용처 grep 0건). 학생 타깃 일정앱에서 '수학 수행 — 3단원 프린트 지참', '학원 — 준비물' 같은 부가 정보를 적을 곳이 없어, 사용자는 별도 메모 탭에 일정과 분리된 글을 남겨야 한다. 애플 캘린더·구글 캘린더 모두 기본 제공하는 필드라 경쟁 대비 공백이며, 데이터 모델은 이미 준비돼 있어 미완성 기능이 방치된 형태다.

**개선안**: EventEditorView에 여러 줄 메모 필드(TextField axis: .vertical 또는 TextEditor)를 추가하고, 그리드 블록 상세/롱프레스 프리뷰와 알림 body에 notes를 노출한다. AI 파서 결과에도 부가 문장을 notes로 흘려보내면 활용도가 높다.

### 🟡 중간 — 편집기에서 시작 시간을 뒤로 옮겨도 종료 시간이 따라가지 않음 — 지속시간 유지 없음 + 종료<시작 역전 저장을 막는 검증 부재

**파일**: `Oneul/Features/Editor/EventEditorView.swift, Oneul/Models/ScheduleEvent.swift`

EventEditorView에는 start 변경에 대한 onChange 핸들러가 없어, 15:00–16:00 일정의 시작을 17:00으로 바꾸면 종료가 16:00에 그대로 남는다(애플 캘린더는 지속시간을 유지하며 종료를 자동 이동). 종료 DatePicker의 `in: start...`(67행)는 새로 '선택'하는 값만 제한할 뿐 이미 역전된 기존 값을 고치지 않고, save()(244-272행)와 단일 일정 경로의 EventActions(ScheduleEvent.swift:145-151)에는 end>start 검증이 전혀 없어 종료가 시작보다 이른 일정이 그대로 저장될 수 있다. 그리드는 최소 26pt로 클램프해(DayGridView.swift:205) 겉으론 조그만 블록으로 보이지만, 시작을 옮길 때마다 종료를 매번 손으로 다시 맞춰야 하는 마찰이 반복된다.

**개선안**: start의 onChange에서 기존 duration을 유지하도록 end를 함께 이동시키고, save() 시 end <= start면 end = start + 기존 duration(최소 5분)으로 보정한다.

### 🟢 사소 — 대체공휴일 미반영 — 공휴일이 일요일과 겹치는 해에는 실제 쉬는 날이 평일 색으로 표시됨

**파일**: `Oneul/Models/DayPlan.swift`

Holidays(DayPlan.swift:130-179)는 양력 8개 + 음력 설날·추석(±1일)·부처님오신날만 하드코딩하고, 관공서 공휴일 규정의 대체공휴일 로직이 없다. 예컨대 삼일절·어린이날·광복절 등이 일요일과 겹치면 다음 월요일이 실제 휴일(학교도 휴업)인데 isRed(140-142행)는 이를 평일로 판정한다. 설·추석도 연휴가 일요일을 포함하면 ±1 스프레드 밖의 대체휴일을 놓친다. 학생이 주 사용자이고 등교 여부가 곧 일정인 앱에서 달력의 빨간 날이 실제와 어긋나는 것은 신뢰를 깎는다.

**개선안**: 어린이날·삼일절·광복절·개천절·한글날·설/추석 연휴에 대해 '일요일(어린이날은 토요일 포함)과 겹치면 다음 첫 비휴일을 대체공휴일로' 규칙을 추가하거나, 연도별 공휴일 테이블을 내장/갱신하는 방식으로 보정한다.
